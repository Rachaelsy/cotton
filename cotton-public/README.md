# 喀什优棉公益平台小程序

## “我的”个人中心

“我的”页统一提供实名认证、我的地块、我的学习、收藏与评价、设置与帮助、关于我们六项个人服务。地块与认证读取当前登录账号的后端数据；课程完成状态和政策收藏目前保存在当前设备；意见评价登录后提交至共享后端，并可查看管理员回复。

实名认证属于可选服务，证件资料仅用于身份核验。金融内容只提供公益科普与官方入口指引，平台不办理贷款、投保、开户或交易业务。

项目每日工作进展统一记录在 [`DAILY_PROGRESS.md`](./DAILY_PROGRESS.md)，面向负责人汇报完成事项、验证结果、风险和下一步计划。

`cotton-public` 是面向棉农的公益农技学习与生产服务小程序。项目以 `demo/index.html` 为产品和视觉参考，复用 `cotton-app` 已验证的农业生产功能，并通过同一套 Node.js + Express + MySQL 后端读取用户、地块、气象、农事记录、专家内容和 AI 数据。

普通内容页面默认使用 WebView 的页面自然滚动；地块、病虫害、气象、专家等复杂页面可单独使用 Skyline，但必须包含明确高度的纵向 `scroll-view`。不要在 `app.json` 全局强制 Skyline，否则首页、资讯和详情等自然文档流页面在真机上会无法上下滑动。

公益管理员统一从 `/admin/login.html?role=admin` 登录。后台左侧包含“政策资讯”“农机服务”“农资服务”“加工服务”“农户管理”和“账号安全”；退出后返回统一登录页，旧的公益运营独立登录页已删除。
账号安全的密码修改复用政策后台 API 通道，可避免服务器代理配置不同步造成的网络连接失败。

本地网页与共享后端开发使用仓库根目录的 `scripts/dev-local.ps1`，统一访问
`http://127.0.0.1/`。本地配置保存在不会提交 Git 的 `.env.development`，不会改动云服务器环境。
本地开发覆盖配置默认使用 Docker Hub 官方 Node、MySQL 和 Nginx 镜像，生产 Compose 仍保留服务器原有镜像地址。若当前网络无法拉取镜像但本机已有可用缓存，启动脚本会自动回退为 `--no-build`；也可显式运行 `scripts/dev-local.ps1 -NoBuild`。修改 `package.json` 或基础镜像后必须恢复联网并重新构建，不能长期依赖旧缓存。
本地公益管理员可通过 `COMMUNITY_ADMIN_PASSWORD` 临时环境变量配合 `db/create_community_admin.js` 创建，密码不会写入项目配置。
公益管理员后台包含“农户管理”，与智能体管理员共享农户数据及新增、编辑、启禁用能力，但不继承商户、订单等其他核心管理权限。

## 当前迁移范围

- 公益平台新首页：顶部当前位置天气与农事提示；常用工具集中展示地块管理、病虫害识别、地块气象、政策资讯、专家讲堂、农事记录、棉知学堂和棉花金融；同级生产服务模块提供农机、农资、加工三个服务入口。
- 生产服务：首页提供农机、农资、加工三个独立模块。农机服务和农资服务不是知识科普页，而是由公益管理员运营的具体产品目录：后台录入名称、机型/品种、品牌、厂家、图片、简介、产品特点、适用条件和地区，只有“已上架”产品会进入小程序。加工服务介绍轧花、检测、仓储三个环节，并通过 `/api/processing-factories` 从数据库读取加工厂列表、县域筛选、地图点位和独立详情；后台可维护名称、经纬度、地址、年加工产能、负责人、联系电话、简介、图片 URL、服务范围和公开核验信息，只有“已发布”记录会进入小程序。首批数据来自自治区公示名单与公开地图 POI 交叉核验；未公开字段不作推测。平台展示公开服务资料，不直接交易、收款或提供推荐、认证与履约担保。
- 棉花资讯：推荐、政策、农技、市场、气象分类列表。
- 政策资讯：首页常用工具入口，下设“政策中心”和“行业资讯”。政策中心按国家、自治区、地区、县级分层；行业资讯按产业、农机、市场、气象分类。列表采用简洁资讯流，详情页按“标题、来源与时间、Markdown 正文、评论”的顺序阅读，并支持登录评论、本机收藏和微信转发。
- 棉花金融：提供种植贷、棉花保险科普、投保指引、期货基础、行情简讯和金融支农政策解读；只做公益科普、材料清单和官方入口指引，不提供贷款申请、投保、开户、交易撮合、荐单或收益承诺。行情简讯当前是“如何看行情”的静态科普，不展示实时价格。
- 棉知学堂：初级、中级、高级阶梯课程，支持图文课、视频课、课程积分和阶段考试。
- 地块管理：列表、地图绘制、新增地块、地块详情。
- 病虫害识别：拍照/相册识别、识别结果和病虫害详情；识别历史与总次数由后端按登录账号隔离，多账号不会共用记录。
- 地块气象：左上角下拉选择当前位置或本人地块，并按所选位置重新获取气象；展示未来 24 小时、未来 7 天趋势、降水/风力/高温风险、灾害预警和农事建议。无地块时仍可查看区域预报，定位不可用时降级为喀什参考预报。
  下拉面板使用页面根层固定浮层，兼容 Skyline 真机点击区域；地块选项不会被顶部容器边界或背景遮罩拦截。
- 专家讲堂：专家内容、视频/图文内容、常见问题和在线提问。
- 农事记录：记录列表、增删改和独立农事日历。
- AI 农技问答、手机号登录及微信一键登录基础页面。

底部导航为“首页 / AI助手 / 我的”。棉知学堂不占用底部导航，继续从首页常用工具进入。首页天气使用定位接口读取真实数据；用户拒绝定位或网络不可用时只展示降级提示。

公益小程序拥有独立、可扩展的管理后台。管理员从统一入口 `/admin/login.html?role=admin` 登录：进入“政策资讯”可使用 Markdown 发布文章；进入“农机服务”或“农资服务”可新增、编辑、上架、下架和删除具体产品；进入“加工服务”可维护加工厂资料、地图坐标和发布状态。产品目录通过 `/api/service-products`、加工厂通过 `/api/processing-factories` 进入小程序，草稿和已下架数据不会公开展示。创建账号和部署步骤见 `cotton-community/README.md`。

农资商城、农机租赁、棉花交易、贷款与保险业务办理、期货开户与交易、商户后台和支付能力不属于公益平台范围。棉花金融仅提供知识教育和官方渠道核验指引。

## 与 cotton-app 共用后端

小程序不会在本目录启动第二套后端。API 地址由 `utils/auth.js` 管理，当前沿用 `cotton-app` 的环境配置：

- `prod`：正式 HTTPS 域名。
- `server`：云服务器 IP。
- `real`：局域网开发机地址，适合真机联调。
- `local`：`127.0.0.1`，适合微信开发者工具模拟器。

当前 `ENV` 设置为 `server`，小程序直接连接云服务器 `http://101.34.207.252`。微信开发者工具调试时需要按项目需要开启“不校验合法域名”；该 HTTP IP 不能作为正式发布配置，正式上传前必须改用已备案且配置 HTTPS 的合法域名。

开发前请在 `utils/auth.js` 中确认 `ENV` 与对应地址。真机不能把 `127.0.0.1` 当作电脑；应使用电脑局域网 IP，并确保手机与电脑处于同一网络、防火墙允许 Node 服务端口。

当前已切换为 `ENV = 'sim'`，微信开发者工具模拟器通过本机 Nginx 统一访问
`http://192.168.0.22`，使用本地 Docker MySQL。采用局域网地址是为了绕过部分 Windows
开发者工具对 `127.0.0.1` 请求的限制。上传体验版或正式版前必须改为 `ENV = 'prod'`；
真机联调则改为 `ENV = 'real'` 并确认 `LOCAL_IP` 是电脑当前局域网地址。
本地私有项目配置已设置 `setting.urlCheck=false`，允许开发者工具请求本机 HTTP 地址；正式版仍由微信平台配置的合法域名控制。网络请求失败时，Console 会输出 `[api-request-failed]` 及实际 URL 和微信错误信息，不记录密码或令牌。

后端仍从 `F:\cotton\cotton-app\server` 启动。首次更新或新增数据库迁移后先执行迁移：

```powershell
cd F:\cotton\cotton-app\server
npm install
npm run migrate:runtime
npm start
```

前端不需要执行 `npm start`，直接用微信开发者工具导入 `F:\cotton\cotton-public`。

修改认证后端代码后，必须重启正在运行的 Node 服务才能加载新代码。PowerShell 如果禁止执行 `npm.ps1`，请使用：

```powershell
npm.cmd run migrate:runtime
npm.cmd start
```

本地 Docker 一键启动：

```powershell
cd F:\cotton
powershell -ExecutionPolicy Bypass -File .\scripts\dev-local.ps1
```

网络暂时无法访问镜像仓库、且本机已有应用和基础镜像缓存时：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev-local.ps1 -NoBuild
```

缓存模式仍会挂载本地源码并自动重启 Node 服务，但不会重新安装依赖；修改 `package.json` 后必须执行完整构建。

认证专项测试：

```powershell
cd F:\cotton\cotton-app\server
npm.cmd run test:public-auth
```

当前本地真机联调地址为 `http://192.168.0.22:3000`。可以先在同一 Wi-Fi 下用手机访问或通过小程序请求 `/api/ping`；响应中的 `database: true` 表示共享 MySQL 已连接。电脑网络切换后 IP 可能改变，需要同步更新 `utils/auth.js` 的 `LOCAL_IP`。

## 首次打开

1. 打开微信开发者工具，选择“导入项目”。
2. 目录选择 `F:\cotton\cotton-public`。
3. `project.config.json` 必须填写实际用于调试的微信小程序 AppID；微信一键登录要求它与后端对应的 AppID 配置一致。
4. 本地调试可在“详情 → 本地设置”暂时勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”。正式发布时必须配置合法 HTTPS request/uploadFile 域名。
5. 确认 `cotton-app` 后端与 MySQL 已启动，再测试登录、地块、气象、农事记录和专家接口。

## 新 AppID 与共用账号的注意事项

不同微信小程序的 OpenID 不相同。共享后端现在支持主小程序和公益小程序两套微信配置：

```env
WX_APPID=原小程序AppID
WX_SECRET=原小程序AppSecret
PUBLIC_WX_APPID=公益小程序AppID
PUBLIC_WX_SECRET=公益小程序AppSecret
```

如果暂时没有配置 `PUBLIC_WX_APPID` 和 `PUBLIC_WX_SECRET`，公益前端会回退使用原小程序配置，便于使用同一个 AppID 联调。换成独立 AppID 后必须填写公益配置并重启后端。

公益小程序发送 `X-Miniapp-Client: cotton-public`，后端据此选择微信配置。手机号账号仍保存在共享 `users` 表；不同小程序的 OpenID 保存在 `mini_program_identities` 表，该表通过无符号用户 ID 外键连接现有用户数据。同一微信开放平台主体下如能取得 UnionID，后端优先将身份关联到已有用户；否则通过授权手机号关联共享账号。

### 注册登录接口

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| 手机号注册 | `POST /api/auth/register` | 创建共享农户账号和农户资料并返回 JWT |
| 密码登录 | `POST /api/auth/login` | 按手机号和密码登录共享账号 |
| 微信一键登录 | `POST /api/auth/wx-login` | `wx.login` + 微信手机号授权，自动注册或关联农户 |
| 登录态校验 | `GET /api/auth/verify` | 小程序启动时验证 JWT 并刷新用户资料 |
| 退出登录 | `POST /api/auth/logout` | 客户端清理 JWT；服务端保留无状态接口 |

## 数据边界

- 共用：农户基础账号、地块、农事记录、气象、专家内容、AI 服务。
- 公益平台独有：资讯栏目、课程体系、学习进度、考试、学习积分、证书、棉花金融科普阅读状态，以及只用于信息展示的农机/农资产品目录。
- 不进入公益平台：商品交易、营销、交易订单、农机支付、微信分账和商户结算。

目前课程与资讯使用前端演示数据，用于确定信息架构和交互。下一阶段应在共享后端增加公益内容 API 和独立数据表，避免把正式运营内容长期写在小程序代码中。

棉花金融首版内容保存在 `utils/finance-data.js`，阅读状态按当前登录账号保存在本机，仅用于展示阅读进度。正式运营前应增加金融科普内容审核、版本、生效时间和来源管理；实时行情若后续接入，必须使用有授权的数据源，展示采集时间、延迟状态、品级、地区、单位和免责声明。

政策中心当前同样使用明确标识的演示数据。正式上线政策内容前，必须建立政策运营后台和审核流程，并保存政策层级、类别、文号、发布单位、发布时间、生效状态、适用地区、申报截止时间及政府原文链接。

## 后续开发顺序

1. 在 `cotton-app/server/.env` 填写公益小程序 AppID 和 AppSecret。

4. 将当前课程和资讯演示数据切换为真实接口。
5. 完成真机定位、图片上传、AI 识别和全流程回归测试。

## 安全要求

- AppSecret、JWT_SECRET、AI Key、天气 Key 只能保存在后端 `.env`，不得写进小程序。
- 小程序只保存服务端签发的 Token。
- 正式环境必须使用 HTTPS，并在微信公众平台配置合法域名。
- 两个前端共用后端不等于共用所有权限；后端仍需对用户和资源归属进行校验。
- 当前 `F:\cotton` 的运行配置已与服务器备份的同名变量同步，本地启动后端可能直接连接线上数据库和服务；执行注册、删除、支付、迁移或测试数据脚本前必须先确认影响范围。
- 同步前的本地配置备份位于 `F:\cotton-history\local-env-before-server-sync-20260807`，真实 `.env` 不得提交到 GitHub。
