## 2026-08-22：播报定位天气与新农户默认地区

1. 智能播报改为优先使用农户点击播放时的手机当前位置天气，首页和全部任务页均按当次定位传递坐标。

3. 播报上下文只记录天气和来源类型，不保存手机精确坐标，兼顾后台审查与位置隐私。
4. 手机号注册、微信首次登录以及公共服务注册的新农户，未填写地区时默认保存“喀什地区莎车县”。

## 2026-08-22：智能播报改为农户按需生成

1. 将首页和全部任务页的播放入口改为农户点击时由后端读取注册地区天气、地块和今日农事，实时生成简短播报文案。
2. 播报文案生成后自动保存并发布，公共服务后台“语音播报”能够继续按农户和日期查看、编辑及管理这些内容。
3. 增加 2 小时缓存和上下文校验；注册地区天气与农事依据未变化时直接复用，降低大模型 Token 消耗。
4. 增加同一农户同一天的并发请求合并，并在 AI 异常时回退最近一次已发布内容，提高真机播放稳定性。
5. 移除后台“一键生成全部农户”入口，播报生成时机由农户实际使用行为驱动。

## 2026-08-22：智能播报批量生成与 Token 优化

1. 将 AI 播报压缩为 60 至 120 个汉字，明确先播最新真实天气、再播今日农事，并去掉寒暄、铺垫和重复表达。
2. 公共服务后台新增“一键生成全部农户”，按选择日期批量生成播报草稿。
3. 后端按地区和去重后的农事内容分组，同组农户只调用一次 AI，并使用组内时间最新的一条真实天气观测。
4. 共享文案不包含农户姓名和地块名称；未填写地区的农户单独处理，防止天气和隐私数据串用。
5. 后台展示覆盖农户数、分组数、实际 API 调用数、跳过数量和失败分组数，方便核对生成效果与成本。
6. 路由和后台脚本语法检查、智能播报自动化测试均已通过；下一步使用真实农户数据验收分组命中率和文案准确性。
7. 修复“地块已有天气但 AI 仍播报暂无天气”：将完整上下文压缩为明确的天气观测与农事数组，并规定天气数组非空时不得输出缺失提示。
8. 将每位农户每日 AI 播报生成上限统一调整为 100 次，覆盖单户接口、批量生成、后台次数提示和自动化测试。
9. 将播报天气来源切换为农户注册地区对应的实时天气；空地区或无法识别地区默认采用莎车县，同地区使用短时缓存减少天气请求。

将新代码安全部署到云服务器，并保证原有服务、数据库和后台网站继续运行。

### 今日完成

1. 梳理本地开发、GitHub、云服务器和 Docker 的完整发布流程。
2. 在覆盖服务器代码前创建代码备份，保留可回滚版本。
3. 配置服务器通过 SSH Key 访问 GitHub，解决 HTTPS 访问 GitHub 超时的问题。
4. 建立服务器更新流程：拉取代码、重新构建 Docker、检查容器状态和服务日志。
5. 排查网页后台 HTTP 502，确认主要原因包括：
   - 应用容器等待数据库；
   - 数据库账号和密码不一致；
   - 新上传环境变量覆盖服务器原配置；
   - `JWT_SECRET` 使用示例值导致服务主动退出。
6. 从服务器备份中核对环境变量并同步本地同名配置，同时保留新增变量。
7. 重新生成符合安全要求的 JWT 密钥并恢复应用启动。
8. 明确生产环境 `.env` 不应被 Git 覆盖，敏感配置不能提交到 GitHub。
9. 梳理线上更新前备份、更新后检查和发生故障时回滚的操作方式。

### 今日成果

- 明确并跑通 Docker 化部署流程；
- 后端可以连接服务器 MySQL；
- 管理员后台恢复访问；
- 建立了生产配置和代码版本分离的安全原则。

### 下一步计划

继续完善首页产品体验，并建设可运营的政策中心。

## 开发第 6 天：公益管理员后台与权限隔离

### 今日目标

为公益小程序建立独立管理员账号和后台权限，避免进入商户、订单等商业管理模块。

### 今日完成

1. 新增公益小程序管理员账号类型和安全创建脚本。
2. 公益管理员接入统一登录页，后端根据账号类型进入对应后台。
3. 公益后台视觉与核心管理员后台统一：深绿色侧栏、白色顶栏和浅灰工作区。
4. 公益管理员侧栏保留与公益小程序相关的功能，移除商户、商品、订单、商业平台和专家账号等无关菜单。
5. 首个内容运营模块为“政策中心”。
6. 新增“账号安全”，支持校验当前密码并修改登录密码。
7. 新密码强制满足长度、大小写字母、数字和特殊符号要求。
8. 修改密码后旧令牌立即失效，退出登录统一返回管理员登录页。
9. 删除没有实际用途的旧公益运营独立登录页，并为旧地址保留兼容跳转。
10. 新增“农户管理”，支持农户列表、新增、编辑、实名标记、启用和禁用。
11. 增加公益管理员专用权限校验，只允许管理农户和公益内容，不继承商户、订单等核心权限。
12. 修复修改密码“网络连接失败”和“接口不存在”，将请求接入稳定的政策后台 API 通道。

### 验证结果

- 公益管理员能够从统一页面登录；
- 后台布局与核心后台一致；
- 政策中心、农户管理和账号安全权限已经建立；
- 退出登录和密码修改后的会话失效逻辑已统一。

### 下一步计划

建立更安全高效的本地开发环境，并继续修复真机业务问题。

## 开发第 7 天：本地开发环境与业务问题修复

### 今日目标

减少“修改一次就部署一次服务器”的低效流程，在本地完成开发、登录和数据库联调。

### 今日完成

1. 新增本地 Docker 热开发环境，两个 Node 服务修改后可以自动重启。
2. 新增本地专用环境变量文件、本地 MySQL 数据卷、上传文件卷和依赖缓存。
3. 本地 MySQL 使用 3307 端口，避免与 Windows 现有 3306 服务冲突。
4. 增加一键启动和停止本地环境脚本。
5. 创建本地智能体管理员和公益管理员账号。
6. 小程序开发环境统一切换为 `sim`，通过本机 Nginx 访问核心 API 和公益 API。
7. 解决微信开发者工具拦截 `127.0.0.1`、请求域名不合法和错误信息不明确的问题。
8. 登录失败时输出脱敏后的请求方法、URL 和微信错误，便于区分域名、后端和数据库问题。
9. 病虫害识别记录改为后端按 `user_id` 保存和查询，解决不同账号都显示相同识别次数的问题。
10. 重设计地块气象模块：
    - 支持当前位置和本人地块下拉切换；
    - 展示当前天气、未来 24 小时和未来 7 天；
    - 增加降水、风力、高温风险、灾害预警、田间指标和农事建议；
    - 无地块时仍可查看当前位置天气；
    - 定位失败时降级显示喀什参考预报；
    - 修复 Skyline 真机中地块选项无法点击的问题；
    - 补充中文和维吾尔语天气文案。

### 验证结果

- 本地 Docker、核心后端、公益服务和 MySQL 可以组成完整开发环境；
- 病虫害识别历史按账号隔离；
- 地块气象页面结构、数据转换和接口检查通过；
- 本地微信登录链路曾验证成功。

### 当前风险与待处理

- Docker Desktop 没有启动时，本地登录和所有 API 都会失败；
- 电脑切换网络后，局域网 IP 可能变化，需要同步检查真机调试地址；
- 正式上传前必须把小程序环境由 `sim` 切换为 `prod`。

### 下一步计划

继续增加老板提出的产业知识模块，并完成真机回归测试。
